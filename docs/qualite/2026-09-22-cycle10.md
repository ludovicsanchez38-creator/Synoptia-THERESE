# Cycle 10 : projets, démonstration et navigation au clavier

## Périmètre et décision

Ce lot poursuit la boucle après la vérification de la release 0.74.0-alpha.
Il ne constitue pas une nouvelle publication : aucun bump, tag, binaire,
déploiement, remplacement de l'application ou message Discord n'est inclus.

Décision explicite de Ludo le 22 septembre : les formulaires de projets restent
masqués et en lecture seule en mode démo, avec un rappel de désactiver ce mode
pour modifier. Les valeurs fictives ne sont jamais enregistrées dans les données
métier. La confirmation de suppression depuis le panneau conserve, elle, le
véritable identifiant et un nom d'affichage masqué.

## Méthode et preuves

Les reproductions utilisent des données synthétiques, des réponses HTTP
interceptées ou des API doublées. Le moteur jetable utilise le port 17393 et
`/tmp/therese-demo-c10/data`. Le port 17293 et les données réelles sont exclus
des tests de mutation.

Chaque changement dispose de tests comportementaux rouges avant correction.
Les revues indépendantes ont ajouté trois cas manquants : même fichier choisi
après changement de projet, styles `::first-line`/`::first-letter` et masquage à
froid. Elles ont aussi reproduit B-943 et la perte du focus après suppression.

Instruments : Vitest, TypeScript, ESLint, Playwright Chromium. Les fixtures
permanentes sont conservées avec les composants et dans
`src/frontend/scripts-recette/`. Les journaux bruts, contrôles de calibration,
captures et revues sont conservés localement sous `.app-loop/cycles/10/`.

Recette UI rejouable : `node src/frontend/scripts-recette/recette-cycle10.mjs`,
sur Vite 1420 et le moteur jetable 17393. Elle couvre panne/reprise du dossier,
lecture seule démo, suppression de facture et les quatre confirmations Contacts,
en clair et sombre à 1280 × 800. Les captures attendent la fin des fondus.

La recette de contraste est volontairement partielle : un résultat indéterminé
n'est pas une conformité. Elle ne remplace pas l'inspection visuelle des
recouvrements, médias, SVG ou géométries complexes.

Diversité des modèles dégradée : Grok a répondu par une erreur d'authentification
expirée, pas une preuve de quota épuisé. Les rôles de reproduction, réparation et
contradiction ont été répartis entre agents distincts. Aucune exécution Claude
n'est revendiquée pour ces lots Astra.

## État de vérification

Snapshot fonctionnel intégré : `eced4f3b`. TypeScript passe. Le lint complet
(`npm run lint`) passe avec zéro erreur et les 27 avertissements du seuil
existant. La vérification des huit composants modifiés n'en relève que trois,
préexistants, sur les dépendances d'effets de MessageList, InvoicesPanel et
MemoryPanel.

- Recette UI : sept parcours en clair et sombre, soit 14 contrôles réussis.
  Les seules réponses 503 sont les pannes volontairement injectées pour tester
  le réessai. Les captures sont inspectées après stabilisation des fondus.
- Images : deux parcours supplémentaires dans l'application réellement servie,
  historique, sélection et confirmation masqués, sans génération. Quatre captures
  inspectées ; aucune erreur console, HTTP ou requête échouée.
- Synchronisation concurrente : même recette Chromium sur `f59f53d9` puis sur le
  correctif. Avant : racine A affichée dans B et bouton Appliquer présent. Après :
  racine B conservée, plan A ignoré, seul le plan B peut être appliqué.
- Contraste : 16 fixtures navigateur passent, dont les états indéterminés requis
  pour les effets non pris en charge. Ce chiffre n'est pas un audit de 16 écrans.
- Réduction des mouvements : les trois scénarios navigateur passent ; points
  immobiles pour les préférences applicative et système, témoin animé sans ces
  préférences.
- Contre-épreuve sur l'ancienne version : 69 échecs parmi les mêmes 82 tests
  comportementaux, dans un worktree isolé sans modification du code de main.
- Le moteur jetable répond sain et son journal contient 104 lignes, sans ERROR,
  au contrôle du 22 septembre à 19:00 UTC.

La première suite complète après intégration compte 2 623 succès sur 2 625,
avec deux échecs dans des tests anciens (accordéon des prompts et périmètre des
contacts). Les cinq tests de ces deux fichiers passent lors du contrôle ciblé.
Le rejeu complet avec deux workers passe : **2 625 tests réussis sur 2 625**,
sans changement d'assertion, sans exclusion et sans relance automatique des
tests en échec (`frontend-complet-borne.json`, sortie 0). Les premiers échecs
restent conservés ; leur diagnostic ne repose pas sur le seul rejeu vert.

La carte différentielle est validée : **1 589 fichiers sur 1 589** dans
`src`, `tests`, `scripts` et `.github`. Les 23 fichiers modifiés ou ajoutés ont
fait l'objet de deux lectures, soit 16 rapports supplémentaires. Le premier
passage du validateur a rejeté des identifiants de rapports dupliqués ; seuls
ces identifiants ont été rectifiés avant le second passage réussi.

Les dix défauts B-934 à B-943 sont clôturés avec leurs preuves. La boucle est
en ZERO_CHECK, sans plateau annoncé. Un arbitrage humain a été demandé sur
deux invariants complémentaires du test de suppression des factures : absence
de suppression sans confirmation et retour du focus après la dernière facture.
Le compteur ne sera pas forcé avant cet arbitrage et les deux rondes propres.

Le diagnostic des deux rouges est conservé dans `diagnostic-suite.md`. Contacts
a dépassé les cinq secondes de délai sous charge. Pour les prompts, un clic
synthétique lancé par MutationObserver avant les effets de montage reproduit
une course ; les trois clics ordinaires et les six recherches passent. Ce cas
est conservé en B-944, différé faute d'atteignabilité utilisateur démontrée,
et non présenté comme corrigé ou comme simple lenteur d'animation.

Limites de ce lot : API synthétiques pour les scénarios fonctionnels ; aucune
génération fournisseur, session Tauri packagée ou installation Windows rejouée.
Le backend n'a pas été modifié. La validation des binaires relève d'une future
release et ne se déduit pas de ces recettes navigateur.
