## 1. Une fiche durable, une seule politique de portée

Créer `MemoryCard` / `memory_cards`, distincte des réglages `Preference` et du Board (`B/models/entities.py:302,315`). Champs : UUID ; type fermé (`preference`, `fait`, `decision`, `correction`) ; titre (120 caractères), contenu (1 200), raison (600, obligatoire pour une décision, jamais inventée) ; source `conversation_id`/`message_id` ; liens facultatifs `contact_id`/`project_id` ; auteur initial/dernier auteur (`therese`/`utilisateur`) ; dates UTC création/modification ; état `active`/`archivee` ; version entière ; protection utilisateur persistante ; sujet normalisé de déduplication. Source obligatoire pour Thérèse, facultative en saisie manuelle ; aucun message recopié. Source supprimée : liens nuls et mention explicite. Pas d’historique intégral des versions.

`scope`/`scope_id` : projet choisi, sinon global, comme R1-2 (`B/services/memory_tools.py:640`) ; jamais `all` ni conversation à l’écriture. Source ≠ cloison. Liens vérifiés côté serveur, sans élargissement demandé par le modèle.

Lecture/recherche/mutation du chat : résolveur `B/routers/chat.py:654`, `souvenirs_globaux_visibles` (`B/services/cloisonnement.py:66`) et **extraction du prédicat existant** `_cloison_contacts` (`B/services/memory_tools.py:438`) vers ce service, partagé avec les fiches. Pas de troisième règle. A exclut B ; `global` exclut les projets ; `all` ouvre explicitement les projets ; erreur = fermé. Cabinet exclut les fiches globales, même préférences, d’un projet : « toutes » signifie toutes les fiches autorisées. Gestion locale : portées visibles, filtrables, sans transmission au modèle.

Migration Alembic après `c9d0e1f2a3b4` (`B/models/database.py:733`) : contraintes/FK, index portée/état/type/liens, sujet unique par portée (normaliser les liens absents : piège NULL SQLite). **Index SQLCipher seulement** : recherche lexicale normalisée titre/contenu, B-tree de sélection ; aucun texte/vecteur dans Qdrant. Connexions existantes (`:941`). Desktop : `create_all`, migrations idempotentes, estampille, sans `upgrade head` (`:1231,1283`) ; couvrir aussi bootstrap, imports et tête Alembic.

## 5. Effacement et portabilité

Étendre l’export global `B/routers/data.py:169,429` et contact `B/routers/rgpd.py:46` : fiches actives/archivées, raisons/sources/liens/versions ; journal/notes restent des activités exportées (`data.py:355`). **Aucun nouvel export lisible** : seule la portabilité explicitement demandée existante les inclut ; sauvegarde chiffrée conservée. Aucun Markdown, stockage navigateur, télémétrie ou cache disque de fiches.

Effacer une fiche retire ligne, index et mentions dérivées des reçus ; archiver la garde lisible sans relecture automatique. Ne jamais réextraire les anciens messages : le reçu d’appel consommé/supprimé empêche une relance identique de ressusciter la fiche. Un souvenir nouveau exige une nouvelle source utilisateur. Les conversations sources restent gérées par leur propre parcours d’effacement ; l’expliquer sans promettre leur disparition.

Effacer un contact supprime ses fiches liées, même sans cascade projet (`B/routers/memory.py:1078,1120`). Effacer un projet supprime ses fiches de portée projet et celles liées explicitement au projet, **sans promotion globale**, dans `_nettoyer_et_supprimer_projet` (`:375`) ; annoncer le compte avant confirmation via `projet_ensemble.py`. Même traitement du journal/notes dans ce périmètre. Anonymisation manuelle/automatique : prolonger le service commun `B/services/rgpd_identite.py:89`, déjà appelé par `rgpd_auto.py:270`. Purge totale : nouvelles tables avant messages/contacts (`B/routers/data.py:688`), arrêt des écritures en vol (`:583,644`), invalidation des états UI ; test de restauration d’une sauvegarde antérieure et information qu’elle peut rétablir les données anciennes.
