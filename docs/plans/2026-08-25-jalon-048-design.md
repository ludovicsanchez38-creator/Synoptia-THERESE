## Lot A - Le Board délibère avec les modèles au sommet

### Constats (code 0.47)
- Le Board passe par `get_llm_service_for_provider` (llm.py:1012) qui a ses
  propres défauts codés en dur (`claude-opus-4-8`, `gpt-5.5`,
  `gemini-3.1-pro-preview`, `grok-4.3`) - périmés, et DIVERGENTS du
  catalogue 0.43.4 de config.py (opus-5, gpt-5.6-sol, gemini-3.7-flash,
  mistral-medium-latest, grok-4.6) qui est relevé à la source à chaque
  release.
- Aucun effort n'est posé sur les LLMConfig du Board ; l'infrastructure
  `LLMConfig.effort` (chantier 10/07) existe mais : OpenAIProvider clampe
  `max`→`high` (périmé : GPT-5.6 accepte `max`), Gemini et Mistral n'ont
  AUCUNE traduction d'effort.

### Vérifications à la source (25/08/2026, docs officielles)

| Fournisseur | Frontier | Paramètre (notre endpoint) | Valeur MAX | Pièges vérifiés |
|---|---|---|---|---|
| Anthropic | `claude-opus-5` | Messages API `output_config.effort` | `max` | `budget_tokens` → 400 ; jamais `disabled` à xhigh/max ; max_tokens large (64k) recommandé ; changer l'effort mi-conversation invalide le cache |
| OpenAI | `gpt-5.6-sol` (alias `gpt-5.6`) | `reasoning_effort` (chat.completions) | `max` | `minimal` absent des fiches 5.6 ; enum : none/low/medium(déf)/high/xhigh/max |
| xAI | `grok-4.6` | `reasoning_effort` | `xhigh` (high = DÉFAUT) | conflit doc (api-reference dit « grok-4.3 only ») → fallback : retirer le param si 400 ; jamais presence/frequency_penalty/stop avec les reasoning models |
| Gemini | `gemini-3.7-flash` | `generationConfig.thinkingConfig.thinkingLevel` | `HIGH` (pas de xhigh ; minimal NON supporté) | MAJUSCULES sur generateContent ; thinkingLevel sur modèle < 3 = erreur ; level+budget ensemble = 400 |
| Mistral | `mistral-medium-3-5` (alias `-latest`) | `reasoning_effort` | `high` (seule valeur documentée pour ce modèle) | **CRITIQUE** : en raisonnement, `message.content` devient une LISTE de chunks (thinking+text) au lieu d'une string, et `delta.content` change de forme en streaming ; Magistral : ligne retirée le 31/07/2026 |

### Design

1. **Source unique** : module `app/services/modeles_catalogue.py` -
   par fournisseur : liste ordonnée (LA TÊTE = frontier), et par modèle :
   `effort_maximal` (la valeur vérifiée ci-dessus) + le clamp éventuel.
   `config.py` (available_models) et `get_llm_service_for_provider`
   consomment ce module. Le Board demande `frontier(provider)` +
   `effort="max"` LOGIQUE.
2. **Traduction « max » par provider** : chaque provider traduit l'effort
   logique vers SA valeur : anthropic `max` (ajouter opus-5/fable-5 aux
   `_EFFORT_PREFIXES` si absents) ; openai `max` pour les 5.6+, clamp
   `max`→`high` CONSERVÉ pour les modèles antérieurs (table par modèle
   dans le catalogue, plus de clamp global) ; grok `xhigh` pour 4.6+
   (hérite d'OpenAIProvider, surcharge de la traduction) avec REPLI :
   si 400 sur reasoning_effort, réémettre la requête sans le paramètre
   (conflit doc xAI documenté) ; gemini : NOUVELLE traduction
   `thinkingConfig.thinkingLevel` (max→HIGH, casse majuscule, jamais
   combiné à thinkingBudget) ; mistral : NOUVELLE traduction
   `reasoning_effort` (max→high) + PARSING du content en liste de chunks
   (extraire les TextChunk, exposer le thinking comme le font les autres
   providers ou l'ignorer proprement - à trancher au challenge).
3. **La synthèse du Board reste sur le LLM principal** de l'utilisateur
   (son choix de réglages) - inchangé.
4. **Détection de dérive** (l'automatisation honnête) : à la première
   délibération du jour (pas au démarrage - ne pas ralentir le boot), pour
   chaque fournisseur AVEC clé configurée : GET /models ; si la tête du
   catalogue est absente → log warning + drapeau « catalogue périmé » sur
   la réponse /api/board/advisors (l'UI peut l'afficher). JAMAIS de
   bascule silencieuse vers un autre modèle : le choix frontier reste
   éditorial, relevé à chaque release comme aujourd'hui.
5. **Coût assumé** : cinq frontiers en raisonnement max = délibération
   plus chère et plus lente. C'est le POSITIONNEMENT du Board (conseil au
   sommet, usage ponctuel). Aucun garde-fou de coût dans ce lot (le
   contrat d'agent P7 est au backlog).

### Tests (TDD, rouges d'abord)
- Le Board cloud construit ses advisors depuis la TÊTE du catalogue (plus
  aucun modèle en dur) ; sabotage : permuter la tête → le test le voit.
- Traduction d'effort par provider : 5 tests de corps de requête (le JSON
  émis contient exactement le paramètre/valeur du tableau).
- Mistral : parsing d'une réponse à chunks (non-stream ET stream, la forme
  qui change en cours de flux).
- Grok : repli sans paramètre sur 400.
- Dérive : tête absente de GET /models → drapeau posé, modèle INCHANGÉ.
- Clamp OpenAI : gpt-5.5 reçoit high quand on demande max ; gpt-5.6-sol
  reçoit max.

## Lot B - P1 : un établi, un tiroir

### Périmètre 0.48 (découpé pour ne pas déborder)
1. **Le tiroir** : une entrée unique « Plus d'outils » (place fixe, rail
   gauche) qui regroupe : Board, Atelier agents, MCP/Connecteurs,
   calculateurs, images, variables, sync Sheets, project.sync. Les 30
   cartes du Centre de capacités DEVIENNENT le contenu du tiroir (le
   composant vit, il change de porte) ; l'accueil ne montre plus le bouton
   Capacités.
2. **L'établi** : l'accueil garde : le champ, le brief, et 4 actions
   métier maximum (Écrire, Retrouver, Préparer, Facturer) à la place des
   7 puces. Brief vide honnête : « Branche tes mails pour que je te
   prépare la journée » + bouton, au lieu de « Rien d'urgent ».

   composeurs (« Demande à Thérèse d'organiser, créer ou agir... ») ;
   l'UNIFICATION PROFONDE des deux composeurs (pièces jointes, slash sur
   l'accueil) reste au backlog (P1-suite) - trop gros pour 0.48.

### Gates

### Mécanique
1. Les IDENTIFIANTS techniques (manifeste 0.44, routes, stores) ne bougent
   PAS - seuls les textes fr-FR changent (manifeste `textes`, libellés de
   composants, raccourcis, `/aide`, onglets Réglages).
2. **Test de lexique** : un test parcourt les textes du manifeste + les
   libellés déclarés et échoue sur tout mot interdit - le lexique devient
   un invariant, pas une passe de nettoyage qui se défait.
3. RULES-DESIGN.md reçoit la table (source unique du lexique).
