# Release v0.57.0-alpha - Le variateur du brief du jour

**Date** : 29 août 2026
**Version** : 0.56.0 -> 0.57.0
**Mode** : pas de PR. Travail commité directement sur `main` après design
challenge et revue de diff.

## Ce qui change

Trois mots dans l'en-tête de la carte « Ton attention aujourd'hui » règlent
combien de lignes le brief développe : **tout / l'essentiel / le minimum**.
« L'essentiel » est le comportement d'avant, donc rien ne bouge sans un geste.

Rien n'est caché : le reste est replié, le bouton annonce ce qu'il contient
(« dont 2 en retard »), le sous-titre compte toujours le total. Rien ne sort de
l'écran : `localStorage`, clé de journée civile, effacé le lendemain, aucun
backend, aucun prompt.

## Design challenge : la fonctionnalité initiale a été refusée

Grok et Codex, saisis séparément sur sept questions écrites pour tuer la
proposition, ont tous deux refusé la version prévue (pastilles muettes
haute/moyenne/basse, champ de texte libre, coupe à 2 éléments). Motifs
convergents : pastilles = la plainte « des petits dessins sans nom » de la
campagne du 28/08 ; deux valeurs sur trois sans effet = commandes placebo ;
champ libre = donnée potentiellement de santé pour zéro effet produit ; couper
sans replier = cacher une facture.

Arbitrage complet : `docs/plans/2026-08-29-plan-brief-du-jour.md`.

## Vérification en vrai navigateur

Banc d'essai à six cardinalités (2, 3, 5, 6, 7, 9 éléments) : le contrôle
n'apparaît pas à 2, offre deux mots de 3 à 6, trois mots à partir de 7.
Flèches clavier, focus visible, persistance au rechargement, purge des clés
d'autres jours, thème sombre. Deux défauts n'ont été vus que là : le focus
dessiné sur une radio d'un pixel hors écran, et « Voir les 1 autre élément ».

## Incident de build

Le premier build a echoue sur `Tests Backend (Python)`, un seul test :
`test_index_des_noms.py::test_le_fichier_commite_est_celui_que_le_code_produit`.

Cause : `docs/INDEX-DES-NOMS.md` porte le numero de version dans son titre, et le
bump 0.56.0 -> 0.57.0 l'a rendu obsolete. Le tag etait deja pousse.

Ma suite locale etait verte parce que je l'avais lancee AVANT le bump. Un vert
d'avant le bump ne dit rien de l'etat d'apres.

Corrige en deux temps : regeneration de l'index, et `scripts/bump-version.sh` le
regenere desormais a chaque bump, pour qu'aucune release ne retombe dedans
(commit `4f310234`). Tag deplace sur le commit corrige, la release n'etant
encore qu'une draft. Second build vert sur les trois plateformes.
