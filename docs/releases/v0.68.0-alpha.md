(skill `boucle-amelioration-app`), lancée par Ludo le 07/09/2026 sur la

## Rouge de CI sur `75e1cfd0` : un quatrième défaut

La CI V2 du commit des correctifs COCO a rougi sur un seul test vitest,
`PanneauxNonModaux` « une modale ouverte PAR-DESSUS garde Échap (S1-3) »,
vert dans la suite complète locale (1 858 tests) mais rouge huit fois sur
huit lancé seul. Instrumenté : au moment d'Échap, `showSettings` est vrai
mais aucun `role="dialog"` n'est monté (Réglages chargés en lazy) et le focus
est encore dans le tiroir ; le raccourci B-645 du cycle (« la surface qui
tient le focus se ferme d'abord ») fermait donc le tiroir et laissait la
modale ouverte, l'exact défaut S1-3 que le test garde. Vert en local seulement
quand un test précédent du même fichier avait déjà chargé le module.
Corrigé (`dc26bc20`, B-658) : le raccourci ne joue plus si une modale du
`panelStore` est demandée ; sabotage vérifié. Une première attribution au
correctif B-657 (même commit) était fausse : le test dépendait de l'ordre
d'exécution, pas du changement.

## Contrôle post-release sur la version installée

Application 0.68.0 lancée depuis `/Applications` (binaire `therese`) sur un
`THERESE_DATA_DIR` jetable, port 17293 libre au moment du test : backend sain
après 16 s (`{"status":"healthy","version":"0.68.0","services":{"database":true,"qdrant":true}}`),
puis `quit` : application fermée en 4 s, port libéré, journal
`Shutdown demandé via /api/shutdown` → `Application shutdown complete` →
`Sidecar terminé (signal 15)`. Un premier essai avait lancé le sidecar
`backend` seul (premier binaire du dossier) : arrêté, sans effet sur les
données réelles.
