## Contenu

### A1 - Board frontier + effort max
- **Catalogue neutre** `app/services/modeles_catalogue.py` : source unique des
  modèles par fournisseur (tête de liste = frontier éditorial, relevé aux
  sources le 24-25/08), politique d'effort à trois états
  (non envoyé | tel quel | traduit), `max_tokens_recommande`.
- **Effort résolu PAR CONSTRUCTION** : `LLMConfig.__post_init__` appelle le
  résolveur unique - aucun chemin de création (défaut, helper, POST
  /config/llm, replis, circuit breaker) ne peut l'oublier. Les providers
  émettent `config.effort_resolu` dans leur syntaxe SANS table locale :
  Anthropic `output_config.effort` (opus-5 : max), OpenAI/Grok
  `reasoning_effort` (gpt-5.6 : max ; grok-4.6 : xhigh), Gemini
  `thinkingConfig.thinkingLevel` (HIGH), Mistral `reasoning_effort` (high),
  Ollama plafond high + dégradation conservées.
- **Les 4 tables de llm.py dérivées du catalogue** (principale, repli par clé,
  circuit breaker + env_map, helper) - fini les modèles périmés en dur.
- **Mistral reasoning** : `normaliser_content` (liste de chunks → texte
  affiché), transport du content BRUT de bout en bout
  (`StreamEvent.assistant_content_brut` → chat.py → `ToolTurn` →
  `continue_with_tool_results` des 9 providers + LLMService) - le rejeu
  multi-tours envoie le message assistant COMPLET exigé par la doc, BUG-108
  préservé (une string ne se rejoue jamais).
- **Repli Grok** : `_stream_request` extrait d'OpenAIProvider ; sur 400 avec
  `reasoning_effort` présent et AVANT tout event, UNE seconde tentative sans
  le champ (aucune duplication possible, garde testée).
- **Board** : chaque conseiller cloud reçoit
  `model_override=frontier(fournisseur)` + `effort_override="max"` +
  `max_tokens_override` (recommandation sourcée ou plancher Board 16000 - à
  effort max le raisonnement décompte du plafond de sortie, 4096 rendait des
  avis vides) + `bascule_circuit=False` : le circuit breaker ne bascule JAMAIS
  silencieusement un conseiller ; circuit ouvert au préchargement = repli
  EXPLICITE sur le service principal, `actual_provider` vrai. Les 3
  `stream_response` du Board exigent `raise_on_error=True` (un avis en erreur
  n'est plus validé vide) et l'erreur finale garde le message précis du
  conseiller.
